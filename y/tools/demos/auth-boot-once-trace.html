student/js/auth.js - the boot runs once

Firebase fires onAuthStateChanged more than once on a normal load: the persisted user first, then again when the ID token resolves against the server. Without a guard the whole dashboard boot ran on each one - profile, chips, avatar, assignments, tiles - which is the second refresh. This drives the real module through those callbacks and counts how many times the boot body actually ran, measured by user-document reads.
