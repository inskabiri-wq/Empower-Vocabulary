# 2026-08-23 - AI Quiz security, the lobby audit, and the pronunciation 0%

Four things asked in one go. Taking them in the order the answers matter.

## 1. Can anyone play the AI Quiz without logging in?

As I first built it: **no**, and that was wrong for this event.

The survey settles it. Seven of the eight mini-games already sign in
anonymously:

| game | join |
| --- | --- |
| bingo, heist, listening, reading, scramble, trust, tug | anonymous |
| Vocab Race (`classroom/js/student.js`) | login required |
| AI Quiz, as first written | login required |

An orientation is precisely the case where a thousand people do not have
accounts yet, and sending them to a login page first ends the game before it
starts. The AI Quiz now signs in anonymously like the rest of the family.

**What that means, stated plainly.** Anyone holding the 5-character code can
join. The code is 5 characters from a 32-character alphabet, about 33 million
combinations, so guessing one is impractical. No history is kept, so there is
nothing to take. A score cannot be tied to a real student record, which is the
trade the other seven games already make. If a future game needs identified
players, that is a different join screen, not a tweak.

Firestore rules are unchanged by this: `isAuth()` is true for an anonymous user,
which is what the other mini-games already rely on.

## 2. Do all the games open the same way?

Now checkable rather than eyeballed: `tools/classroom-lobby-check.js` asserts
every host page has the session code, the QR tile, the join link, a player count
and a start button, that every game has a matching join screen, and that both
load the shared stylesheets.

First run found two real gaps, both in the ORIGINAL Vocab Race pages, not in the
seven mini-games:

- `classroom-teacher.html` had no join link. The URL was already being built for
  the QR code, it simply was never put on screen, so it was the one lobby whose
  address could not be read out. A display-only anchor was added and populated
  from the same variable.
- `classroom-student.html` uses `sessionCodeInput` and asks for no name.

The second one is **deliberate and left alone**. Vocab Race students are signed
in already, so the account supplies the name and there is nothing to type. The
different id is historical. Renaming ids in the oldest and most used game to
satisfy a checker would risk a working game for a cosmetic win, so the exception
is written into the checker instead of being rediscovered later as drift.

All nine hosts and all eight join screens now pass. Vocab Race's ids were
checked against their JS references afterwards: `sessionCodeInput` 4 refs,
`startGameBtn` 4, `joinScreen` 2, and the rest 1 each. Nothing was broken.

## 3. Pronunciation showing 0%

This one is worse than the label suggests.

`student/js/pronunciation.js` has no marking at all. Its only `score` variable
ranks text to speech voices. Nothing in the activity ever decides an answer is
right, so `score` stays 0, and the session was saved through the same pipeline
as a quiz: `percentage: 0`.

Two visible symptoms, and one invisible one that matters more:

- the end screen said **"0/10 (0%)"** and **"Keep practicing!"** to a student
  who had just done the whole exercise properly
- the teacher's Recent Activity row said **0%**
- **`teacher/js/activity.js` averaged `percentage || 0` across a student's
  sessions and flagged anyone under 50% as needing attention.** Practising
  pronunciation pulled a student toward being reported as struggling. That is a
  false alarm generated by using the feature as intended.

`percentage || 0` cannot tell "scored zero" from "never scored", which is why
the filter has to happen before the average rather than inside it.

Fixed in four places:

| where | now |
| --- | --- |
| `student/js/auth.js` | unscored activities save with NO percentage field, plus `unscored: true` and `wordsPractised` |
| `student/js/games.js` | end screen reads "10 words practised", and no missed-word review |
| `student/js/games.js` | no assignment completion check, since 0 would have failed one |
| `teacher/js/activity.js` | row reads "🎙️ 10 practised"; the needs-attention average counts only marked sessions |

**Not finished, and worth knowing:** 17 other places still average
`percentage || 0` (student-detail, students, modals, reports-admin). Old
pronunciation rows already in Firestore still carry `percentage: 0` and will
keep dragging those particular numbers until they are filtered too. I fixed the
one that mislabels students and stopped new rows being written wrong, rather
than sweeping 17 call sites at the end of a long change and risking the reports.
The list is above; it is mechanical but wants its own pass.

## 4. Does the AI Quiz hold 1000 students?

Measured against the emulator with the real host code, `tools/demos/aiquiz-scale.html`:

| players | lobby render | ladder | session doc |
| --- | --- | --- | --- |
| 30 | 0.15 ms | 10 docs | 181 B |
| 300 | 0.15 ms | 10 docs | 181 B |
| 1000 | **0.21 ms** | **10 docs** | **181 B** |

All three are flat, which is the whole point. Compare the Vocab Race
measurement: 13.5 ms per render at 300 players and 81 seconds of rendering
across a game, because it draws a card per student and rebuilds the list on
every score write.

- the lobby draws ONE number, so it does not grow with the room
- the ladder is a `limit(10)` query, so it reads ten documents whether the room
  holds 30 or 1000
- the session document every phone listens to stays 181 bytes at every size,
  because the questions live in their own document read once per phone

Also verified earlier, end to end with the real rules: a student cannot write
another student's score, and `increment` does not race.

**Still not tested:** real phones on a venue network, and 1000 sign-ins at once.
An emulator cannot answer either. A rehearsal with a few dozen real handsets is
the only thing that will.
